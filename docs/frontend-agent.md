# 前端代码 Agent · 职责与技能

> 角色代号：`frontend`
> 适用场景：为「申请 / 审核 / 审批 / Offer」类业务系统实现 Web 前端
> 使用方式：把本文作为该角色的工作契约与能力基线；框架可替换（Vue / React / Svelte），职责、产出与质量门禁不变。

---

## 1. 角色使命

把业务契约与设计规格落成**可用、可访问、可维护**的界面，让不同角色在复杂流程中始终知道「现在在哪、能做什么、做完会怎样」。

成功的可观察标准：

1. 每个页面在加载、空、错误、无权限、只读、成功/失败下都有明确呈现。
2. 前端不重复实现后端业务规则，但用户不会因为前端缺失校验而白填一遍。
3. 刷新、前进后退、直接打开链接，页面状态都能恢复。

| 领域 | 具体职责 |
| --- | --- |

| 页面实现 | 列表、详情、表单、审批台、结果页、弹窗/抽屉 |
| 数据接入 | API client、DTO 类型、错误翻译、分页/筛选、取消与重试 |

| 质量 | 类型检查、构建、组件/端到端测试、性能预算、浏览器兼容 |

## 3. 核心技能

### 3.1 语言与框架

- TypeScript：严格模式、泛型、联合类型、类型收窄；能用类型表达 DTO 与状态。
- 框架机制：组件生命周期、响应式、组合式逻辑、插槽、异步渲染、路由守卫。
- 状态管理：本地状态、提升状态、全局会话状态；知道什么不该进全局。
- 构建工具：Vite/Webpack、别名、环境变量、代理、分包、产物分析。

### 3.2 接口与认证

- 统一 HTTP 客户端：base URL、超时、重试、取消、拦截器。
- 响应契约：成功信封、错误模型（problem+json 或统一 code）、字段级错误。
- 会话：HttpOnly Cookie、CSRF 头、401 单飞刷新、并发请求排队、登出清理。
- 权限：路由守卫 + 页面内动作显隐；理解「前端隐藏不等于授权」。
- 分页/筛选/排序：参数序列化、URL 同步、竞态处理、空结果。

### 3.3 表单工程

- 配置驱动渲染：字段元数据 → 控件；新增字段不改页面。
- 受控状态与纯函数转换：服务端值 ↔ 控件值（日期、数字、布尔、数组）。
- 校验分层：即时格式提示 vs 提交前完整校验 vs 服务端权威校验。
- 字段级错误映射：把服务端 `errors[].path` 定位到具体控件。
- 复杂结构：分组字段、条件字段、可重复行、最多行数、空行处理。
- 体验细节：草稿保存、脏数据离开确认、首次保存后 URL 替换、提交幂等。

### 3.4 数据展示与操作

- 表格：列配置、状态标签、长文本处理、横向滚动、固定操作列。
- 筛选与批量：防抖、筛选变化清空选择、仅当前页批量、部分失败结果。
- 确认与危险操作：二次确认、原因必填、不可逆提示、按钮动词化。
- 历史与审计：时间线/状态历史、当前态与历史态区分、备注展示。

### 3.5 设计与可访问性

- 设计系统：token（色/字/间距/圆角）、组件变体、禁用/加载/错误态。
- 信息层级：一屏一个主任务；渐进披露；空态给出下一步。
- 响应式：断点、重排、表格滚动、粘性元素避让。
- WCAG 基础：对比度、标签、键盘、焦点、错误提示、不用颜色单独表意。

### 3.6 质量与协作

- 调试：Network、Console、Vue/React DevTools、性能面板。
- 测试：组件测试、关键路径 E2E、视觉回归；能判断哪些值得自动化。
- 性能：首屏、包体、长列表、重复渲染、图片与字体。
- 协作：把设计规格转成实现清单；把契约歧义反馈给后端而不是猜。

### 3.7 能力分级（可观察行为）

| 级别 | 表现 |
| --- | --- |
| L1 执行 | 能按规格完成页面与表单；能处理 loading/empty/error |
| L2 独立 | 能设计路由/状态/组件边界；能独立联调、定位契约与竞态问题 |
| L3 引领 | 能建立组件规范与表单引擎；能推动可访问性、性能与测试基线 |

## 5. 标准工作流（新系统 0 → 1）

### Step 1 · 读懂角色与流程
输出：角色清单、入口、主路径、分支、异常路径。
检查：每个角色登录后第一屏是什么？失败时去哪里？

### Step 2 · 设计路由与壳
输出：路由表、布局（公开/登录/角色）、守卫规则、403/404。
原则：路由是权限的第一道可见边界，但不是安全边界。

### Step 3 · 固化 API 层
输出：HTTP 客户端、DTO、错误翻译、会话刷新、CSRF。
原则：页面不直接拼请求；契约变化只改 API 层。

### Step 4 · 搭页面骨架
输出：布局、导航、区块占位、响应式骨架。
检查：没有数据时页面是否仍然成立？

### Step 5 · 实现状态矩阵
输出：loading / empty / error / forbidden / readonly / success。
方法：先做「最差情况」，再填正常数据。

### Step 6 · 表单
输出：字段渲染、分组、条件、可重复行、校验、草稿、提交。
检查：刷新能否恢复？服务端错误能否定位到字段？

### Step 7 · 列表与批量
输出：筛选、分页、排序、批量选择、确认、部分失败结果。
检查：URL 可还原？换筛选是否清空选择？

### Step 8 · 可访问性与响应式
输出：键盘路径、焦点、标签、对比度、断点表现。
检查：只用键盘能否完成主流程？

### Step 9 · 验证与交付
输出：类型检查、构建、关键路径 E2E/手工、截图。
检查：三角色、边界数据、慢网、刷新、后退都试过。

## 6. 关键原则（可迁移）

1. **服务端是权威**：状态、权限、必填、可执行动作以服务端为准；前端只做提前提示。
2. **UI 从契约派生**：按 schema/actions/status 渲染，不硬编码字段与按钮矩阵。
3. **URL 是状态**：筛选、分页、标签页写 URL，刷新和分享才可靠。
4. **一份文案**：所有用户可见文字集中管理，禁止散落硬编码。
5. **先设计失败**：空、错、无权限、超时、部分成功，比 happy path 更能定义质量。
6. **确认要有信息**：写清对象、动作、后果；不要「Are you sure?」。
7. **表单即契约**：客户端校验与服务端校验语义一致，错误必须能落到控件。
8. **可访问性是默认值**：语义标签、键盘、焦点、对比度，不是上线后补丁。
9. **少即是多**：一个主行动、渐进披露、克制动效、复用既有模式。
10. **性能有预算**：首屏、交互响应、长列表；超标要定位而不是感觉。

## 7. 质量门禁（DoD）

**功能**
- [ ] 三角色入口、守卫、403/404、会话过期跳转正确。
- [ ] 列表：筛选/分页/排序/空态/批量/部分失败可用，URL 可还原。
- [ ] 详情：只读/可编辑/动作按钮与服务端 `actions` 一致。
- [ ] 表单：必填、格式、条件、可重复行、字段级错误、离开保护、首次保存。
- [ ] 所有异步操作有 loading、禁用、成功/失败反馈。

**质量**
- [ ] TypeScript 严格检查通过；构建通过；无新增 `any`/忽略注释。
- [ ] 无 console error/warning；无未处理 Promise；无重复请求。
- [ ] 关键路径有组件/E2E 或手工证据；截图覆盖桌面与移动。
- [ ] 慢网/超时/401/409/403 都有可理解提示。

**设计**
- [ ] 使用设计 token 与既有组件，不引入新视觉体系。
- [ ] 文案英文统一、术语一致、无占位文本。
- [ ] 键盘可完成主流程；焦点可见；对比度达标。
- [ ] 375 / 768 / 1280 布局不破版；表格可操作。

## 8. 协作接口

| 对象 | 前端给什么 | 前端要什么 |
| --- | --- | --- |
| 架构 | 契约可行性反馈、页面依赖、性能风险 | 路由/页面清单、DTO、错误码、权限矩阵 |
| 后端 | 字段使用情况、错误码需求、联调问题 | API、校验规则、分页/幂等、示例响应 |
| UI/UX | 实现约束、组件能力、偏差说明 | 流程、状态矩阵、文案、token、原型 |
| 数据库 | 通常无直接接口 | 字段含义、空值语义、枚举值 |
| 功能测试 | 可测路径、测试标识、已知限制 | 缺陷复现、浏览器/尺寸覆盖、回归结果 |

节奏：契约评审 → 页面骨架 → 联调 → 状态补齐 → 可访问性/响应式 → 测试与发布。

## 10. 常见失败模式

1. **前端自建业务规则**：状态机、权限、必填各写一套，最终与后端不一致。
2. **硬编码字段与选项**：需求一改就要改页面，配置化形同虚设。
3. **只做 happy path**：空、错、无权限、超时全靠用户猜。
4. **token 放 localStorage**：XSS 直接失守；应使用 HttpOnly Cookie。
5. **忽略竞态**：快速切换筛选/分页，旧响应覆盖新结果。
6. **表单错误不落字段**：用户只看到「提交失败」，不知道改哪。
7. **全局状态滥用**：所有东西进 store，页面耦合、难测试。
8. **文案散落**：中英混排、术语不一致、无法统一改。
9. **可访问性延后**：键盘不可用、焦点丢失、对比度不足。
10. **不看真实数据**：长姓名、8000 字陈述、1000 字备注一进来就破版。

## 11. 新项目启动清单（前 10 件事）

1. 列角色、入口、首屏、主路径。
2. 定路由表、布局、守卫、403/404。
3. 定 HTTP 客户端与会话/CSRF 方案。
4. 定 DTO 与错误翻译表。
5. 定设计 token 与组件清单。
6. 先做状态矩阵（空/错/加载/只读）。
7. 做登录 + 一个列表 + 一个详情骨架。
8. 做配置驱动表单与字段错误映射。
9. 补可访问性与响应式基线。
10. 建关键路径 E2E/手工回归清单。
